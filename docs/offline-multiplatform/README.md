# خطة POS Next: الأوفلاين وتعدد المنصات

الهدف: تطبيق واحد بواجهة واحدة يعمل على **الويب** و**Windows (exe عبر Electron)** و**Android (عبر Capacitor)**، أونلاين وأوفلاين، مع مزامنة موثوقة وسجل مركزي للفواتير الفاشلة.

## الخلاصة

- **التطبيق قوي وظيفيًا:** لا حاجة لإعادة كتابة الواجهة.
- **طبقة الأوفلاين الحالية غير كافية للإنتاج:** توجد 11 مشكلة حرجة، أخطرها أن فشل الفاتورة لا يبقى له أثر في الخادم، وأن المسار الأونلاين قد يكرر الفاتورة، وأن الفاتورة الأوفلاين تُرحل بتاريخ المزامنة لا تاريخ البيع.
- **النقل المباشر إلى Electron وAndroid خطأ:** يجب إصلاح نموذج البيع والمزامنة أولًا.
- **الحل:** مسار بيع واحد يحفظ محليًا أولًا، ثم Outbox في الجهاز، وInbox في الخادم يحفظ كل فاتورة قبل معالجتها.
- **المدة التقديرية:** 5 إلى 7 أشهر للمسار الكامل حسب حجم الفريق. أول مرحلتين في 7 أسابيع تقللان معظم المخاطر المالية.

## القرارات المتخذة في الخطة

| القرار | السبب |
|---|---|
| الفاتورة تُحفظ محليًا أولًا في كل الأوضاع | لا يضيع البيع بسبب الشبكة |
| الأوضاع الثلاثة مشغلات لمحرك واحد | لا تختلف النتيجة باختلاف الوضع |
| كل فاتورة تدخل Inbox الخادم قبل معالجتها | الفشل يصل إلى السجل تلقائيًا |
| توسيع `Offline Invoice Sync` | يحتفظ بالقيد الفريد والتقرير |
| SQLite على Electron وAndroid، وDexie على الويب | الويب لا يملك SQLite أصليًا |
| واجهة تخزين على مستوى المستودعات | تجمع المحركين دون كود منصة في الواجهة |
| رمز جهاز مع `auth_hooks` للتطبيقات الأصلية | الكوكي لا تعمل خارج نطاق الموقع |
| التفضيلات تبقى في `localStorage` | تجنب تعديل غير ضروري |
| المرجع هو `version-16` في مستودع `champion-sys` | قرار الفريق، ولا يُدمج BrainWise دون طلب |
| Android: بلوتوث وطابعة Wi-Fi. سطح المكتب: طابعة محددة في الإعدادات أو نافذة النظام. الويب: بلوتوث وChrome وQZ بطابعة افتراضية | قرار الفريق |

## قرارات تحتاج تأكيدكم

الخطة تعمل بالافتراض المذكور حتى يتغير.

| # | السؤال | الافتراض الحالي | يؤثر على |
|---|---|---|---|
| 1 | هل الفروع خاضعة لـ ZATCA المرحلة الثانية؟ وما سياسة الإيصال أوفلاين؟ | نعم، والوضع اللحظي افتراضي، وإيصال الانقطاع مؤقت | الإيصال، المرحلة 5 |
| 2 | ما موديلات أجهزة Android وطابعاتها؟ | طرق الطباعة محسومة، والموديلات تحدد نوع البلوتوث المطلوب | المرحلة 4 |
| 3 | ما أقصى مدة أوفلاين مسموحة؟ | 72 ساعة | السياسة والأمان |
| 4 | هل تُنشر التطبيقات عبر متجر أم توزيع داخلي؟ | داخلي، مع توقيع Windows | المرحلتان 3 و4 |
| 5 | كيف تتعاملون مع المشروع الأصل BrainWise وترخيص AGPL؟ | Fork مع دمج دوري، وإتاحة المصدر | التراخيص والصيانة |
| 6 | هل يجوز الرصيد والمحفظة أوفلاين؟ | أونلاين فقط | سياسة الدفع |
| 7 | Sales Invoice أم POS Invoice أم كلاهما؟ | Sales Invoice افتراضيًا مع دعم الاثنين | المعالج |

## المصطلحات

| المصطلح | المعنى |
|---|---|
| Outbox | طابور في الجهاز يحفظ ما يجب إرساله ولا يفقده |
| Inbox | سجل في الخادم يحفظ ما وصل قبل معالجته |
| `offline_id` | معرف ثابت للفاتورة يمنع تكرارها عند إعادة الإرسال |
| Port | واجهة مجردة تنفذها كل منصة بطريقتها |
| Adapter | تنفيذ Port لمنصة محددة |
| Backoff | زيادة الفاصل بين المحاولات |
