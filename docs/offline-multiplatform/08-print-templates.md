# 08. قوالب الطباعة

## الهدف

يصمم المدير قالب الطباعة بنفسه في Desk بلغة HTML وCSS وJinja، كما يفعل مع Print Format في Frappe. يُعرض القالب على الجهاز نفسه، فيطبع دون اتصال على كل المنصات: الويب وسطح المكتب وAndroid.

## ما يوجد اليوم

- **مع الاتصال:** يعرض الخادم Print Format في Frappe. أما Android فيرسمه الخادم صورة PNG ثم يرسلها بأوامر ESC/POS.
- **دون اتصال:** يطبع التطبيق تصميمين مكتوبين في الكود، `buildReceiptHTML` و`formatInvoiceToReceiptLines`، ولا يستطيع أحد تعديلهما. لا تعمل أي صيغة مخصصة دون اتصال، ولا تُطبع حتى الفاتورة المرسلة إذا انقطع الاتصال.
- **بيانات الفاتورة دون اتصال:** لا تحمل عنوان الشركة ولا رقمها الضريبي ولا الشعار ولا سطور الضرائب.
- **ما يقبله كل ناقل:**
  - المتصفح وQZ وElectron تقبل HTML.
  - Bluetooth وUSB والشبكة على Android والويب لا تقبل إلا أوامر ESC/POS.

## التصميم

### القالب

نوع مستند جديد هو `POS Print Template`. لا يكتبه إلا `Nexus POS Manager` أو `System Manager`. حقوله:

| الحقل | الغرض |
|---|---|
| `template_name` | اسم القالب |
| `enabled` | يعمل أو لا |
| `paper` | عرض الورق: 58mm أو 80mm أو A4 أو A5 |
| `html` | القالب بصيغة Jinja |
| `css` | التنسيق |
| `copies` | عدد النسخ |
| `preview_invoice` | فاتورة لمعاينة القالب عليها |

يحدد كل ملف نقطة بيع قالبه في `POS Settings` عبر الحقل `print_template`، ويستطيع كل طابعة على الجهاز أن تختار قالبًا غيره.

### العرض

- **على الجهاز:** يعرض القالب Nunjucks، وهي مكتبة JavaScript بصيغة Jinja. ونستخدم الدالة نفسها في معاينة Desk، فما تراه في المعاينة هو ما يُطبع.
- **الأمان:** قالب Nunjucks يستطيع تنفيذ كود JavaScript، ولذلك لا يكتب القوالب إلا المدير.

### ما يصل القالب

أسماء الحقول قريبة من Frappe، فأغلب قوالب Print Format تعمل بتعديل قليل.

| الاسم | محتواه |
|---|---|
| `doc` | الفاتورة: الأصناف، وسطور الضرائب، والدفعات، والإجماليات، والعميل، والتاريخ، والرقم، ورقم الفاتورة دون اتصال، والمرتجع، والعملة |
| `company` | الاسم، والعنوان، والرقم الضريبي، والهاتف، والبريد، والموقع، والشعار (`logo` بصيغة data URI حتى يُطبع دون اتصال) |
| `pos_profile` | الاسم، والمستودع، والعملة، وما يحتاجه القالب منه |
| `cashier` | المستخدم واسمه الكامل |
| `customer` | الاسم، والرقم الضريبي، والجوال، والعنوان |
| `print` | الورق، والاتجاه من اليمين لليسار، واللغة، ورقم النسخة، وهل هي إعادة طباعة |

ودوال يستدعيها القالب:

| الدالة | عملها |
|---|---|
| `_()` | الترجمة |
| `format_currency(value, currency)` | تنسيق المبلغ بالعملة |
| `format_date` و`format_datetime` و`format_number` | تنسيق التاريخ والرقم |
| `qr(text)` | صورة رمز QR |
| `barcode(text)` | صورة باركود |
| `money_in_words(value, currency)` | المبلغ كتابةً |

### الوصول إلى الجهاز

تُنزَّل القوالب وبيانات الشركة والشعار مع بيانات البدء، ثم يسحبها التطبيق تزايديًا بالتاريخ `modified` وتُحفظ على الجهاز. وتحفظ بيانات الفاتورة المطبوعة سطور الضرائب الكاملة، وبيانات الشركة والعميل.

### الطباعة

| المنصة | الطريق |
|---|---|
| سطح المكتب | نافذة مخفية تطبع HTML بعرض ورق القالب، دون نافذة حوار، على الطابعة المحددة، بعدد النسخ |
| الويب | نافذة الطباعة في المتصفح، أو QZ بصيغة HTML |
| Bluetooth وUSB والشبكة | يُرسم HTML صورة على الجهاز نفسه بعرض 384 أو 576 نقطة، ثم يُرسل بأمر الصورة `GS v 0` |

**إن لم يُحدَّد قالب** يبقى السلوك الحالي كما هو.

## ما لم يتغير

- تبقى قوالب Print Format في Frappe تعمل مع الاتصال.
- يبقى مصمم الطباعة الحراري في Desk كما هو.
- يبقى تصميما الكود احتياطًا عند غياب أي قالب.
